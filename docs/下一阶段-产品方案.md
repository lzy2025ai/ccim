# ccim 下一阶段：产品方案

> 状态：已确认。四块：设备管理、Skill 共享、应用和需求池、知识库拆分。按第二节的顺序做，每块单独提 issue。

## 一、定位

ccim 是一个人的 Agent 平台：底座是自己电脑上的 Claude Code / Codex，网页是主界面，飞书、微信是手机上的入口，
几台电脑连成一个平台。和 Claude / Codex 原生应用比，我们的长处是：

1. **多台电脑**：一个网页管几台电脑上的 Agent，服务器做总控，手机上也能用
2. **手机上用得顺**：国内网络下手机直接打开网页或在飞书、微信里用，不用自己解决网络
3. **任务面板**：等你处理的、正在干活的、最近在跟的，一眼找到

下一阶段往两个方向走：**把「多台电脑」做深**（设备管理、Skill 共享），**让平台能按需长出功能**（应用、需求池）。

## 三、设备管理

用户故事：我在手机或别的电脑上，想看看家里那台 Mac 上有什么文件、磁盘还剩多少、清掉没用的东西，
或者指着某个文件夹让 Agent 帮我处理。

入口：「设置 → 电脑」列表里点一台电脑，进入这台电脑的页面。

第一版：
- **概况**：型号、系统、磁盘用量、在不在线、ccim 版本、这台电脑上的 Agent 和正在干的活
- **文件**：按文件夹浏览（路径导航、列表、按名字 / 大小 / 修改时间排序），新建文件夹、重命名、移到废纸篓、
  上传、下载；文档和图片点开用已有的预览
- **带 Agent**：选中文件或文件夹 →「让 Agent 处理」，选这台电脑上的一个 Agent，开一个对话，工作目录就是这个文件夹，
  选中的文件附在消息里
- **磁盘清理**：扫描在后台跑、显示进度，结果分组：
  - 缓存（各种应用和开发工具的缓存、废纸篓）：能重新生成，可以直接清
  - 开发产物（node_modules、编译输出、很久没动的项目里的虚拟环境）
  - 大文件（超过 1 GB、很久没打开的）
  - 下载文件夹里的旧文件
  - ccim 自己的（旧的工作目录、旧的稳定版、日志）

  每项显示大小、上次使用时间、删了能不能找回。勾选后清理：缓存直接删，其余移到废纸篓。
  可以「让 Agent 看看」：把扫描结果交给 Agent，给出建议再由你勾选

先不做：在电脑之间复制文件、改文件权限、在这里编辑文件内容（文档预览里能编辑的照旧）。

安全：
- 能访问整个用户主目录；系统目录不显示
- 删除一律移到废纸篓（缓存类除外），每次操作记一条记录
- 经过服务器删除、清理别的电脑上的文件时，再点一次确认

实现要点：新接口都走现有的按电脑转发（X-Machine），各台电脑只处理自己的文件；扫描结果缓存，重扫按需。

## 四、Skill 共享

用户故事：我在平台上装好一个 Skill，所有电脑上的 Agent 通过 ccim 和我对话时都能用；各台电脑本地自己装的 Skill 照常可用。

第一版：
- 平台上的「Skill」页：列表、安装（GitHub 地址、上传压缩包、从某台电脑已有的 Skill 导入）、停用、删除、更新
- 每台电脑一份完整的 Skill 库，同步方式和知识库一样（后改的算数）
- 挂载：通过 ccim 的对话启动会话时，把平台 Skill 库作为一个本地插件加载（Claude Code 的 SDK 支持按会话加载本地插件）。
  插件里的 Skill 带插件名前缀，不会和本地同名的 Skill 冲突
- 默认所有 Agent 都挂上；Agent 设置里可以去掉某几个

先不做：Codex（要先确认它能不能按会话挂 Skill）；在终端里直接用平台 Skill（以后可以加「装到这台电脑」）。

安全：Skill 里可能带脚本，同步过去就等于在那台电脑上跑这段代码。只有主人能装；安装时显示来源。

## 五、应用和需求池

### 1. 应用是什么

一个应用 = **一个页面 + 一个数据目录 + 给 Agent 的说明（Skill）**，各放在自己的目录里，不改平台核心代码：

- 页面在隔离的 iframe 里跑（和文档预览一样），通过平台提供的少数几个接口做事：读写自己的数据、打开文件预览、
  在页面旁边挂一个 Agent 对话、调用应用自己的动作
- 数据放在应用自己的目录里，Agent 照 Skill 里写的规则往里放东西（例如「下载的书放进书架」）
- **动作**：需要在后台做的事（例如发布到公众号要用密钥调接口）写成应用目录里的脚本，由平台来跑，密钥存在钥匙串里。
  每个应用第一次跑动作时要你批准
- 网页左侧导航加「应用」，每个应用一个入口；应用目录用 git 管着，每次改动一个提交，可以退回

### 2. 需求池

用户故事：我在和某个 Agent 干活，它做不到某件事（没有地方给我预览文章、没有书架），我或者它把这件事提成需求，
开发 Agent 评估后，简单的直接做掉，复杂的留着等我有空一起定。

第一版：
- 所有 Agent 多一个「提需求」的工具；你也可以在群里 @ 开发 Agent 提，或者直接在需求页里写
- 需求页：每条有标题、描述、谁提的（链接到那段对话）、状态、处理记录、关联的应用 / issue / PR
- 状态：新提 → 评估中 → 直接做 / 等你确认 → 开发中 → 待验收 → 完成 / 不做
- 开发 Agent 按下面的规则分流：

| 直接做（做完通知你，可以退回） | 等你确认 |
|---|---|
| 新建或修改应用、Skill（做完直接上线） | 改平台核心代码（走 issue → PR → 验收） |
| 不需要新权限、不花钱、不接外部账号 | 要新权限：访问新目录、跑脚本、联网发布 |
| 产品上没有明显取舍 | 要外部账号、密钥，或产品取舍不明确 |

### 3. 两个例子

**书架**（第一个应用，先手工做）：
- 导入：Agent 下载的书按 Skill 放进书架；也能上传。第一版支持 EPUB、PDF
- 阅读：目录、记住读到哪、选中一段直接问
- 讨论：每本书一个对话挂在右侧，Agent 能读到这本书的内容（转成文字存一份）
- 书在哪台电脑就从哪台电脑读，别的电脑和手机上照样能看

**文章库**（由开发 Agent 按需求做）：
- 公众号 Agent 写好的文章自动进文章库，按草稿 / 已发布分
- 公众号样式的排版预览、改稿（复用文档预览里已有的公众号视图和编辑）
- 一键发到公众号草稿箱，之后再看要不要直接发布。公众号的接口权限、密钥由公众号 Agent 在提需求时和你对齐

## 六、知识库拆分

- **对话知识库**：只有一个，不再新建小库；收藏默认进它。现在已有的几个库合进来，原来的库名变成标签
- **文档知识库**：放 PDF、Word、Markdown、网页，分两步：
  1. 转成文字，做全文检索，给 Agent 一个「查文档」的工具，返回段落和出处，回答里的引用能点开定位
  2. 再加向量检索（模型选本地的还是接口的到时再定），和全文检索一起用
- 多台电脑之间同步原文件，检索索引每台电脑自己建

## 七、已确认

1. 设备管理能访问整个用户主目录
2. 经过服务器删除、清理别的电脑上的文件时，点一次确认就行，不再输验证码
3. 平台 Skill 默认挂给所有 Agent
4. 现有的小知识库合并成对话知识库，原来的库名变成标签
5. 应用可以带后台脚本，每个应用第一次跑时要批准
6. 开发 Agent 能直接做的需求，做完直接上线、通知、可以退回
7. 业务上的账号和密钥（比如公众号）由对应的 Agent 在提需求时去对齐，不在平台方案里定
