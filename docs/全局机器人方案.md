# 另一个产品方向：全局一个机器人，在聊天里切换项目

> 存档，暂不做。现在的做法是每个项目目录一个机器人。

## 设想

整台电脑只配对一个飞书机器人。在聊天里用命令选项目：

- `/projects`：列出可用的项目（已登记的目录）
- `/cd 项目名`：这个聊天切到某个项目，之后的消息都在那个目录里交给 Claude
- 每个「聊天 × 项目」各有一个会话，切回来能接着聊

## 和现在的做法比

| | 每个项目一个机器人（现在） | 全局一个机器人 |
|---|---|---|
| 配对 | 每个项目扫一次码 | 只扫一次 |
| 飞书里的样子 | 一个项目一个联系人，一眼看出在和谁说话 | 一个联系人，要记得当前在哪个项目 |
| 进程 | 每个项目一个，可以单独开关 | 一个进程管所有项目 |
| 群聊 | 拉哪个机器人进群就是哪个项目 | 群里还要再选项目 |
| 风险 | 一个机器人只能动一个目录 | 一个机器人能动所有登记的目录 |

## 什么时候值得做

- 项目很多、来回切换频繁，扫码和管理多个机器人变成负担；
- 或者想要一个「总管」，跨项目查状态、派任务。

目前还没想到非它不可的场景，先存档。

## 做的话要改什么

- 登记表从「项目 → 机器人」改成「机器人 → 项目列表」；
- bridge 里按「chat_id + 当前项目」找会话，`Chat` 的 cwd 跟着项目走；
- 审批卡片标题已经带项目名，不用改；
- 后台进程从每项目一个变成全局一个，`ccim start/stop` 的语义要重新定。
