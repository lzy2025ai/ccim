# ccim 多设备与多底座：产品方案

> 状态：方向已确认，按四期做，每期单独提 issue。

## 一、定位

ccim 走到现在：

1. 把本机的 Claude Code / Codex 接到飞书、微信，出门也能接着干活；
2. 机器人多了，做了网页平台来管 Agent，又有了跨设备的 Skill 共享、Agent 管理、群聊；
3. 总控搬到服务器上，公网也能用。

下一步：**用户所有的机器（自己的电脑、云服务器）都能接进来，平台上统一安装、配置、使用上面的 Agent。**

原则不变：**Agent 和数据都在用户自己的机器上，平台只做管理和转发，不存用户的东西。**

## 二、边界

- 平台管到「设备在不在线、装了哪些底座、配好没有、上面有哪些 Agent」为止。
- 设备上的具体事情（查磁盘、看日志、改配置）交给那台设备上的 Agent 做，平台不另做运维监控、批量执行命令这类功能。
- 平台只转发聊天和配置，不提供远程执行任意命令的入口。

## 三、现状

| 能力 | 现状 |
|---|---|
| 设备注册到总控（配对码、签名通信） | 已有（多台电脑与账号.md） |
| 平台上看设备和设备上的 Agent、文件管理、磁盘清理 | 已有（#100） |
| 多账号、共享电脑 | 已有，默认关 |
| Linux | 接入脚本认 Linux，平台常驻只是后台跑起来，没有开机自启；没在真实 Linux 服务器上验收过 |
| Windows | 不支持 |
| 平台上配底座 | 只有 DeepSeek Harness 能在设置里填 Key；Claude Code、Codex 要在那台机器上先装好、登录好 |
| 平台上装底座 | 没有 |
| 底座的写法 | Claude Code / Codex / DeepSeek Harness 在十几个文件里分别判断，加新底座要到处改 |

## 四、分期

| 期 | 做什么 | 完成标准 |
|---|---|---|
| 一 | **Linux 服务器能用**：systemd 常驻、开机自启；用普通用户跑，不用 root；设备上没装底座也能接入，平台上照样显示；Linux 上设备页的文件管理、磁盘清理能用 | 一台全新的 Linux 服务器从一条命令开始接入，重启后自动上线，在平台上和它上面的 Agent 对话 |
| 二 | **底座接口**：把现有三个底座搬到统一接口上；`ccim base` 命令和平台页面都能安装、填 Key、登录 | 在平台上给一台空服务器装好一个底座、配好、开出 Agent，全程不用登录服务器 |
| 三 | **新底座**：按需要一个一个接（OpenCode、Hermes、OpenClaw 等），每个只写一个适配文件 | 新底座的 Agent 能对话、用 ccim 工具 |
| 四 | **Windows** | 同第一期的完成标准 |

### 底座接口（第二期）

每个底座说清楚这几件事，平台按它统一显示和操作：

- 怎么装、装好没有、版本
- 要什么配置：API Key（表单字段由底座声明）还是账号登录
- 登录方式：服务器上没有浏览器，用「平台上显示登录链接或验证码，手机上完成」；各底座是否支持要先实测
- 怎么开对话、接着聊、停下；输出事件怎么转成 ccim 的消息
- 有哪些模型、思考深度
- ccim 工具通过 MCP 提供（`toolsock.py` / `mcpstdio.py` 已经给任意底座用）

平台页面上的「安装 / 配置」按钮和 `ccim base` 命令走同一套实现：按钮就是让那台设备去执行这条命令。

### Key 和登录态

Key、登录态只存在那台设备本地。经过总控时加密转发，总控不落盘。

## 五、先不做

- 运维监控（CPU、内存曲线，告警）、批量执行命令
- 总控托管给多个用户注册使用
