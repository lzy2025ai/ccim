# ccim 智能体平台：产品方案

> 方向已确认，按三期做。把 `ccim web` 从「控制台」升级成「智能体平台」：在浏览器里和 Agent 对话、管理 Agent、
> 用项目（群聊）组织多个 Agent 协作，以及定时任务。

## 一、定位

**现在**：ccim 是「把 Claude Code / Codex 接到飞书、微信的桥」，`ccim web` 是管理这些桥的控制台。

**以后**：ccim 是一个跑在自己电脑上的**智能体平台**。

- 底座是 Claude Code 和 Codex，用本机的登录和额度，能读写本机文件、跑命令。
- 网页是主界面：对话、管理 Agent、项目协作、定时任务都在这里。
- 飞书、微信是 Agent 的「分身入口」：出门在外用手机和同一个 Agent 说话，做完回到电脑上还能接着看。

和 Claude / Codex 桌面版比，多出来的是：**Agent 可以长期存在、有自己的角色和工作目录，能被拉进项目一起干活，
能定时跑，能从手机上找到。**

## 二、概念

| 概念 | 是什么 | 现在对应什么 |
|---|---|---|
| **底座** | Claude Code 或 Codex | 已有（`--agent claude / codex`） |
| **Agent** | 一个长期存在的智能体：名字、头像、角色说明、底座、默认模型和思考深度、工作目录（可以没有）、接入的渠道 | 现在网页里叫「项目」的那一个个机器人 |
| **对话** | 和某个 Agent 的一次会话（一个 Claude / Codex 会话），可以随时接着聊 | 已有：飞书私聊、群、话题、微信里的每个对话 |
| **项目** | 一个「群聊」：有名字、工作目录（可以没有），拉进来一个或多个 Agent，在里面派活 | 没有 |
| **任务** | 在项目里派给某个（些）Agent 的一件事，有过程、结果、状态 | `ccim ask` 的雏形 |
| **定时任务** | 按时间自动给某个 Agent / 项目派的任务 | 没有 |

几个规则：

- **一个 Agent 有很多个对话**：网页里开的、飞书私聊、飞书群、微信里的，各是各的对话，互不串。
  想在一处看另一处聊了什么，用已有的「查看其他对话」。
- **没有工作目录的 Agent**：给它一个自己的空目录（`~/.ccim/agents/<名字>/`）当工作区，适合写作、调研、问答这类不碰代码的活。
- **项目里的 Agent 在哪个目录干活**：项目指定了工作目录，就在项目目录；没指定，就在 Agent 自己的目录。
- **同一个 Agent 可以在好几个项目里**，每个项目里各是一个独立的对话。

## 三、功能

### 1. 对话（像 Claude / Codex 桌面版）

用户故事：我打开网页，选 Claude 或 Codex，选好模型和思考深度，直接开始聊，让它干活。

第一版：
- 左侧对话列表（按时间），新建对话
- 新建时选：和哪个 Agent 聊；或者「临时对话」：直接选底座、模型、思考深度、工作目录（可不选）
- 对话里：流式显示回答；Claude 每一步在做什么（读了哪个文件、跑了什么命令）可以展开看；需要批准的操作弹按钮
- 输入框：发文字、贴图片、拖文件；干活时可以补充、可以停下
- 对话中途换模型、思考深度（和飞书里 `/model`、`/effort` 一样）
- 临时对话可以「保存为 Agent」
- 能打开飞书、微信、终端里的对话接着聊（这个 Agent 的所有对话都在列表里，标出来自哪）

以后：搜索对话；对话分享导出；斜杠命令补全。

### 2. Agent

用户故事：我要一个「写周报的助手」「前端开发」「测试工程师」，各有各的角色和习惯，长期用；需要时还能在飞书里找到它。

第一版：
- Agent 列表：名字、头像、底座、在不在线、正在干什么、最近对话
- 新建 / 编辑：名字、头像、角色说明（会作为它的系统提示）、底座、默认模型和思考深度、工作目录（可不填）
- Agent 详情：它的所有对话（网页、飞书、微信）、它在哪些项目里、接入的渠道
- 渠道：接飞书（扫码建机器人）、接微信、断开；就是现在控制台里的那些功能
- 直接和它开对话（进入「对话」界面）
- 删除（不删工作目录里的文件）

现有的「项目」全部自动变成 Agent：名字沿用机器人名，工作目录就是原来的项目目录，飞书、微信接入照旧。

### 3. 项目（群聊）

用户故事：我在做「官网改版」，拉进前端、文案、测试三个 Agent。在群里 @前端 改首页，@文案 写新的产品介绍；
同一个需求我想看看 Claude 和 Codex 谁做得好，就同时 @ 两个，各做各的，对比结果。做到一半发现缺个设计，直接在群里新建一个设计 Agent 拉进来。

第一版：
- 项目列表；新建项目：名字、工作目录（可不填）、拉哪些 Agent
- 项目界面像群聊：
  - 消息流：我派的任务、各 Agent 的进度和回答，按时间排
  - 输入框里 `@` 选 Agent（可以选多个，也可以 @所有人）
  - 每条任务卡片显示：派给谁、各自的状态（排队 / 干活中 / 完成 / 出错）、用时，点开看过程
- 同一个任务派给多个 Agent：各自在自己的会话里做，互不干扰；结果并排对比
- 群里新建 Agent：填几项就建好、直接进群
- 成员管理：拉人、移出
- 每个 Agent 在项目里的对话可以单独点开，接着和它一对一聊

以后：
- Agent 之间接力（A 做完自动把结果交给 B）、主管 Agent 自动拆任务分派
- Agent 在干活中发现缺人，自己提议新建 Agent（要用户点头）
- 项目共享的资料区、项目记忆

### 4. 定时任务

用户故事：每个工作日早上 9 点，让「日报助手」汇总昨天的 git 提交，发到飞书群；每周五下午让「测试」跑一遍回归。

第一版：
- 新建：给谁（某个 Agent，或某个项目里的某个 / 某几个 Agent）、做什么（任务内容）、什么时候（每天 / 工作日 / 每周几 / 每月几号的几点，或者一次性）
- 结果发到哪：留在网页里（项目或对话里），可选同时发飞书或微信
- 列表：下次什么时候跑、上次结果；暂停、立即跑一次、编辑、删除
- 运行记录：每次的结果和用时，点开看过程
- 电脑睡着或 ccim 没在运行时错过的：醒来后补跑一次，并标明是补跑

## 四、和现有功能的关系

- 飞书、微信接入、审批、进度卡片、`/model` 等斜杠命令、`ccim ask`、查看其他对话：全部保留，变成 Agent 的能力。
- 命令行里的「项目」先不改名，网页里叫 Agent；以后再统一。
- 微信「一个号管多个项目」变成「一个号管多个 Agent」，`/项目` 切换的就是 Agent。
- 现在的控制台功能（状态、启动停止、日志、扫码接入）都并进 Agent 界面，不单独保留控制台。

## 五、技术方案要点

- **网页也是一个渠道**：和飞书、微信一样实现渠道接口（发消息、发卡片、更新卡片……），卡片和进度实时推到浏览器。
  对话、审批、排队、打断、补充这些逻辑全部复用，网页和飞书里的体验一致。
- **一个常驻的平台进程**：跑网页、网页里的对话、项目里的任务、定时任务。飞书、微信接入还是各自的进程（现有的稳定、能单独重启）。
- **Agent 的登记从「按目录」改成「按编号」**：现在登记表以项目目录为键，没有工作目录的 Agent、同一目录的多个 Agent 都放不进去。
  新建 Agent 登记表，现有项目自动迁移过去，旧命令照常能用。
- **项目里多个 Agent 同时改同一个目录会打架**：普通派活时共用项目目录；「对比测试」时，项目目录是 git 仓库的话，
  每个 Agent 用一份独立的副本（git worktree），做完各自是一个分支，方便对比和挑一个合并。
- **只在本机打开**：继续只监听 127.0.0.1。手机上用飞书、微信。

## 六、分期

| 期 | 做什么 | 做完能干什么 |
|---|---|---|
| 一 | 平台底座（平台进程、网页渠道、Agent 登记表和迁移）+ **对话** + **Agent** | 在网页里像桌面版一样和 Claude / Codex 聊；建、管 Agent，接飞书、微信 |
| 二 | **项目（群聊）**：@ 派活、多个 Agent 同时做同一件事并排对比、群里新建 Agent | 多个 Agent 协作和对比测试 |
| 三 | **定时任务** | 让 Agent 按时自己干活、把结果发到群里 |
| 以后 | 远程访问（手机浏览器）、Agent 接力和自动分派、Agent 自己提议新建 Agent | |

每期做完都能单独用、单独验收。

## 七、已定的决定（2026-10-14）

1. **项目里 Agent 默认看不到彼此的消息**：每个 Agent 只看到派给自己的任务；要把 A 的结果给 B，在 A 的回答上点「转给…」或派活时引用。
2. **对比测试各用一份副本**：项目目录是 git 仓库就给每个 Agent 一份独立副本（git worktree），做完各是一个分支；不是 git 仓库就提示会互相覆盖、让用户确认。
3. **角色说明只作为系统提示**：存在 ccim 里，不写进工作目录的 CLAUDE.md / AGENTS.md。
4. **定时任务错过了醒来补跑一次**：不管错过几次只补一次，并标明是补跑。
5. 产品名先继续叫 ccim。
6. **全局默认模型和思考深度 Claude Code、Codex 各设一套**（现在的 `ccim config --global` 只管 Claude Code，一期一起支持 Codex）。
7. **「对话」里新建对话默认是临时对话**：直接进空白对话，在输入框下选底座、模型、思考深度、工作目录；想和某个 Agent 聊的人会去 Agent 页，「对话」里只留一个次要入口。
