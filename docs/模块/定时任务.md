# 定时任务

改 schedules.py 或 ccim schedule 前先读。

- `ccim/schedules.py`：定时任务（#9）。存平台 state.json 的 schedules（next_run 存盘），运行记录 web/schedule-<编号>.jsonl（run 按 id 合并）。
  平台进程里每 30 秒检查一次：到点就跑，下一次从「现在」往后算，所以错过几次都只补一次（比预定晚 5 分钟以上标 catchup）；
  只跑一次的跑完就暂停。发到已有对话、群聊的（交给主 Agent 或 @ 人）每次也标章节「任务名 · 月-日」（#355），每隔几分钟跑的不标，不出声的那次去掉。
  只跑一次的跑完就暂停。给 Agent：默认 session=same，一直用网页对话 s-<任务>-<Agent>（#132，`schedules.listed`：进对话列表、带「定时」标签，
  用户能接着问；每次运行走 `_run_chat`，记成 sched 提问并加章节，连续两次出错先 reset 会话）；session=new 每次 s-<任务>-<运行>，不进对话列表。meta 里都有 schedule；
  给项目：走 `projects.dispatch`（一起做），等各人做完。deliver 用 `channels.send_once` 私聊主人
  Agent 自己建（#122）：`ccim schedule`（cli.py，走本机平台的 HTTP 接口）。会话启动时给助手进程环境变量 CCIM_CHAT / CCIM_CHANNEL / CCIM_AGENT /
  CCIM_PROJECT（`Chat.ccim_env`），PATH 前面加 ~/.ccim/bin（只放 ccim 一个软链，`ccim_bin`）。网页对话里建的是 kind=chat：到点在原对话里跑（`_run_chat`），
  记录里那条任务带 sched；飞书、微信里建的交给 Agent、deliver 回那个渠道。quiet：提示里让它没事只回 QUIET，WebChannel 不记这种回答，
  `Logs.drop` 去掉那条任务、推送 drop。频率 every（每隔几分钟）。Claude 的 CronCreate / CronList / CronDelete 在 ccim 会话里禁用
- 任务面板和红点（#447）：定时任务发起的那一轮（summary 的 sched_last，chat_view 带 sched_turn）不进「正在干活」「等你处理」、不算任务面板角标（等批准的照常），
  你在里面回了话那一轮照常算。结果靠数字红点（#447 第二轮改成数次数）：summary 每行带 unseen = 几次没看的结果（完成或出错，quiet 不算，
  所以后来一次不出声的不会把前面没看的清掉）、unseen_at = 最近那次的时间。没看 = done_at 晚于定时任务的 seen_at、也晚于那次发结果的对话
  （run 记录里的 chat）的 seen_at。列表里有新结果的排最上面（服务端排一次，网页合并几台电脑后再排一次），数字在头像右上角；
  侧栏「定时」是所有没看的次数加起来。打开定时任务 /api/schedule/seen 记 seen_at；
  新建时记一次，启动时没有 seen_at 的补成现在（以前跑的不算新结果）。schedule 推送会让网页重取一次整体状态。
- 网页定时任务页（#449）：左边任务列表，打开某个任务右边直接是它的对话（openSchedule → openChat，和对话页同一套，能接着追问），
  顶上 `schedBar` 一条：名字、频率、下次 / 正在跑 / 已暂停，立即跑一次、暂停 / 恢复，更多里编辑、运行记录、删除。哪个对话 `schedChatId`：
  发到对话、群聊的就是 target.id；交给 Agent 且接着同一个对话的是 s-任务-Agent，每次新开的是最近一次运行的 chat；从没跑过、交给项目的没有对话，显示原来的任务详情。
  运行记录在 #/schedules/<编号>/runs（current.sub = runs），带「回到对话」。对话模式下 schedule 推送只重画顶上那条（`refreshSched`），不重开对话；
  `viewing` 认 `schedOn`，打开就算看过。对话打不开（删了）退回任务详情。
